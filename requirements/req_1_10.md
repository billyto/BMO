# Mark Translations for Anki Export (v1.10)

## Context
Sig is a menu bar Danish ↔ English translator. While studying, the user wants to flag useful translations and later turn them into Anki flashcards. Today translations only live in History, which is off by default (`historyEnabled = false`) and capped at 20 items (`AppSettings.historyMaxCount`), so it can't be the source of truth for cards.

## Decisions
1. **Export mechanism:** file export first (Anki text import). AnkiConnect is deferred to a later version.
2. **Card direction:** Danish → English only. Danish on the front, English on the back, regardless of which direction the translation was made in.
3. **After export:** cards stay in the list, flagged as exported, and are not exported again.
4. **Default deck:** `Dansk::fraSig` (editable in Settings).

## Requirements
1. The user can mark/unmark a translation from the popover result, the Services/hotkey floating window, and History rows
2. Marked cards persist independently of History (survive History being disabled, cleared, or trimmed)
3. One card per Danish phrase — marking the same Danish text again from another surface shows it as already marked
4. A list view shows marked cards, with pending vs exported state, and lets the user delete cards
5. "Export" writes all pending cards to an Anki-importable text file and marks them exported
6. Re-importing the same card into Anki updates it rather than creating a duplicate
7. Optional IPA (from espeak-ng) is included on the back of the card when available

## Tasks

### Task 1: Card model (`Sources/BMOLib/AnkiCard.swift`)
- `struct AnkiCard: Codable, Identifiable, Equatable` with `id: UUID`, `danish: String`, `english: String`, `ipa: String?` (var), `sourceLang: Language`, `createdAt: Date`, `exportedAt: Date?` (var)
- Failable builder `AnkiCard(source:translated:from:to:ipa:)` that uses the existing `danishText(source:translated:from:to:)` helper (`PhoneticsService.swift`) to pick the Danish side; returns nil when neither side is Danish
- `static func key(for danish: String) -> String` — trimmed (whitespace + newlines) and lowercased; used for duplicate detection
- Keep `HistoryItem` unchanged (no schema migration — same reasoning as IPA in v1.9)

### Task 2: Card list logic + persistence
- Pure value type (e.g. `struct AnkiCardList`) holding `[AnkiCard]` with mutating helpers, so the logic is unit-testable without the `AppSettings` singleton / `UserDefaults.standard`:
  - `toggle(_ card:)` — adds if the Danish key isn't present; removes if present **and pending**; no-op if already exported (prevents accidentally re-adding an exported card as a fresh one with a new GUID)
  - `contains(danish:)`, `card(forDanish:)`, `delete(id:)`, `markExported(ids:at:)`, `clearExported()`
  - `pending` / `exported` computed views; newest first
- `AppSettings` wraps it as `@Published var ankiCards`, persisted as JSON under a new `"ankiCards"` key (same pattern as `translationHistory`). No cap; if it ever grows past ~1000 cards, move storage to a file in Application Support
- New settings in `AppSettings`:
  - `ankiDeckName: String`, default `"Dansk::fraSig"`; an empty value falls back to the default
  - `ankiIncludeIPA: Bool`, default `true` (only has an effect when espeak-ng is available)

### Task 3: Mark button on every translation surface
- Icon: `bookmark` / `bookmark.fill`; help text "Save for Anki" / "Remove from Anki list" / "Exported to Anki" (exported cards show filled, toggle is a no-op)
- **Popover** (`FilledResult` in `TranslatorView.swift`): third `SigIconButton` next to Speak/Copy, keyboard shortcut ⌘D (⌘S, ⌘K, ⌘↩ are taken). Pass the already-computed `viewModel.danishIPA` into the card
- **Floating window** (`translationCard` in `TranslationResultWindow.swift`): `SigIconButton.compact` under Copy. Hidden when `detectedSource == nil` (non-DA/EN source, no Danish side). Pass `viewModel.danishIPA`
- **History** (`HistoryRow` in `HistoryView.swift`): add to the hover action group. A marked row keeps the bookmark visible when not hovered — the group's `.opacity` currently applies to all buttons, so the bookmark needs to sit outside it or get its own visibility rule

### Task 4: Anki list view (`Sources/BMOLib/AnkiListView.swift`)
- New `ActiveView.anki` case wired up in `TranslatorView.body`, with the same slide transition as History
- Layout mirrors `HistoryView`: `ViewHeader(title: "Anki", onBack:)`, scrolling rows (Danish on top, English muted below), delete on hover
- Exported rows dimmed with a small "Exported" label; pending rows full strength
- Bottom: primary "Export N new cards" button (disabled when N = 0); secondary "Clear exported" in the header trailing slot
- Empty state: "Bookmark a translation to add it here"
- Footer: new `FooterButton` (`rectangle.stack`) next to History in `FooterRow`, with a small badge showing the pending count

### Task 5: Exporter (`Sources/BMOLib/AnkiExporter.swift`)
- Pure `static func makeFile(cards: [AnkiCard], deck: String) -> String`:
  ```
  #separator:tab
  #html:true
  #notetype:Basic
  #deck:Dansk::fraSig
  #tags column:3
  #guid column:4
  <Danish>\t<English><br><small>/ipa/</small>\tfraSig\t<card UUID>
  ```
  - Column 1 → Basic "Front" (Danish), column 2 → "Back" (English + optional IPA), column 3 → tags, column 4 → GUID
  - Escape `&`, `<`, `>` in field text; newlines → `<br>`; tabs → single space
  - GUID = `card.id.uuidString` so re-imports update the existing note
- Export flow (on `@MainActor`, triggered from the list view):
  1. Take `pending` cards
  2. If `ankiIncludeIPA` and espeak-ng is available, fill missing `ipa` via `PhoneticsService` (cards marked from History won't have it) and save it back to the card
  3. Write to `~/Downloads/Sig-Anki-<yyyy-MM-dd-HHmm>.txt` (UTF-8, timestamped so exports never overwrite each other)
  4. `NSWorkspace.shared.activateFileViewerSelecting([url])`
  5. `markExported(ids:)` only after the write succeeds; on failure show the error inline in the list view and leave cards pending
- No `NSSavePanel`: presenting it steals focus and closes the `.transient` popover mid-export

## Technical Notes
- Anki text-file headers (`#separator`, `#html`, `#notetype`, `#deck`, `#tags column`, `#guid column`) need Anki 2.1.55 or later; check them against the current Anki manual (docs.ankiweb.net → Importing → Text Files) before finalizing the format
- Anki localizes stock note type names when a collection is created. If the user's "Basic" note type has a different name, the import dialog lets them pick it — document this rather than adding a setting
- Anki also flags duplicates by first field (Danish), which backs up the GUID-based update behavior
- The app is not sandboxed, so writing to `~/Downloads` needs no entitlement
